# ADR-019：ボードの状態は、ボードごとに1つの goroutine だけが読み書きする

- 状態：確定
- 決めた人：Claude の提案をユーザーが承認
- 記録した日：2026-11-28

## 状況

サーバーでは、複数の接続から同時に操作が届く。ボードの状態（付箋の一覧と、接続している画面の一覧）を、データ競合を起こさずに読み書きする方法を決める必要があった。

## 選択肢

- ボードの状態を mutex で守り、それぞれの接続の goroutine が直接読み書きする
- ボードごとに1つの goroutine（Hub）を動かし、ボードの状態は Hub だけが読み書きする。ほかの goroutine は channel で Hub に頼む

## 決定

- ボードごとに Hub の goroutine を1つ動かし、そのボードの状態は Hub だけが読み書きする
- 接続ごとの goroutine は、登録、登録の取り消し、操作を channel で Hub に送る
- Hub は接続へ送るメッセージを、接続ごとの送信待ちの channel に入れる。空きがなければ待たずに、その接続を切り離す

## 理由

- 状態を読み書きする goroutine が1つだけなので、mutex を使わずにデータ競合を防げる
- Hub が操作を1つずつ処理するので、操作の順番がサーバーで1つに決まり、全員に同じ順番で配れる
- goroutine と channel の使い方を学ぶという、このアプリの目的に合う

## 受け入れたトレードオフ

- Hub が1つの操作に時間をかけると、そのボードのほかの操作も待たされる。M3 で DB に書き込むときは、書き込みの時間に上限を設ける必要がある
- 遅い接続を切り離すので、切り離された画面は接続が切れたと表示する。M2 ではつなぎ直さない

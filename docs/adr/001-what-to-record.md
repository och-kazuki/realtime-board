# ADR-001：ADR に書くもの

- 状態：確定
- 決めた人：ユーザーが決定
- 記録した日：2026-11-27

## 状況

設計を段階ごとに分けて進めると、確定した判断が各段階の設計書に散らばり、あとから参照しにくくなる。

## 選択肢

- 迷った判断も含めて、判断するたびに ADR に書く
- プロジェクト全体で確定した判断だけを ADR に書く

## 決定

- `docs/adr/` にはプロジェクト全体で確定した判断だけを書く。ユーザーが決めたものと、Claude の判断で決めたものの両方を含む
- 段階ごとに変わる判断はその段階の要件や設計書に書き、ADR には書かない
- 保留している判断は ADR に書かない
- 確定した判断を変えるときは、元の ADR の中身は書き換えずに新しい ADR を書き、元の ADR の状態を「置き換え済み（ADR-番号）」にする
- 各 ADR には状態、決めた人、記録した日、状況、選択肢、決定、理由、受け入れたトレードオフを書く

## 理由

ADR を、確定した事実と仕様を参照する場所として使うため。

## 受け入れたトレードオフ

検討の途中の経緯と、段階ごとの判断は ADR からは追えない。それらは各段階の設計書と PR で追う。

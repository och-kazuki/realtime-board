# ADR-003：設計書の分け方

- 状態：確定
- 決めた人：Claude の提案をユーザーが承認
- 記録した日：2026-11-27

## 状況

1つの設計メモにまとめた設計は長く、読むのが苦痛だった。画面ごと、機能ごとに設計書を分けて、段階ごとにレビューできるようにしたかった。

## 選択肢

- 1つの設計メモにまとめる
- 設計書を種類ごとに分け、さらに段階、画面、機能ごとにファイルを分ける

## 決定

- 設計書を要件（段階ごと）、画面設計（画面ごと）、機能設計（機能ごと）、画面とサーバーで共通の取り決め、ADR に分ける
- 1つのファイルには1つの段階、1つの画面、または1つの機能だけを書く
- 置き場所と読む順番は [docs/README.md](../README.md) に書く

## 理由

読む量が減り、変わった画面や機能の設計書だけをレビューできるため。

## 受け入れたトレードオフ

ファイルの数が増えるので、どこに何があるかを docs/README.md で案内する必要がある。

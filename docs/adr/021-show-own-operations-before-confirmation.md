# ADR-021：自分の操作は、サーバーの結果を待たずに表示する

- 状態：確定
- 決めた人：Claude の提案をユーザーが承認
- 記録した日：2026-11-28

## 状況

M2 では付箋の操作をサーバーに送り、サーバーが受け付けた操作を全員に配る。操作した本人の画面に、自分の操作をいつ表示するかを決める必要があった。最初の設計メモでは、まずサーバーの結果を待ってから表示する作り方にし、慣れてから変えるとしていた。

## 選択肢

- サーバーの結果が届いてから表示する
- サーバーの結果を待たずに表示し、サーバーの結果で確定するか、表示を戻す

## 決定

- 画面は、サーバーが確定した付箋の一覧と、送ったがまだ結果の届いていない自分の操作（確定待ち）を分けて持つ
- 画面に表示する一覧は、確定した一覧に、確定待ちの操作を送った順に反映し直して作る
- 結果か `error` が届いたら、その操作を確定待ちから除く。結果は確定した一覧に反映する

## 理由

- 追加した付箋にすぐ文字を入力でき、手を離した位置に付箋が残る。M1 と同じ使い心地を保てる
- 結果を待つ作り方では、結果が届くまで追加した付箋が一覧になく、すぐに編集を始める流れを保つための処理が別に要る
- 確定した一覧はサーバーが配った順番どおりに操作を反映して作るので、ほかの人の操作と入れ違っても、最後にはどの画面もサーバーと同じになる

## 受け入れたトレードオフ

- サーバーが受け付けなかった操作は、いったん表示されてから消える
- 結果が届くまでの短い間、自分の画面とほかの人の画面で表示が違う
- 確定待ちの操作と、操作ごとの `requestId` を管理する処理が増える

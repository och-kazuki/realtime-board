# ADR-002：開発の進め方

- 状態：確定
- 決めた人：Claude の提案をユーザーが承認
- 記録した日：2026-11-27

## 状況

最初は1つの設計メモにすべてを書いていたが、長くて読みにくく、作る段階ごとにレビューしにくかった。

## 選択肢

- 全体の設計を1つの設計メモにまとめてから作る
- 段階ごとに、その段階の要件と設計を書いてから作る

## 決定

- アプリは M1〜M4 の段階に分けて作る。ロードマップの Phase と区別するため、アプリの段階は M で呼ぶ
- 段階ごとに、要件、設計、レビュー、実装、確認の順に進める
- 設計と実装は別の PR にし、設計の PR をマージしてから実装に入る
- 手順の詳しい内容は [docs/README.md](../README.md) に書く

## 理由

その段階で作る分の設計書だけを、まとめてレビューできるため。

## 受け入れたトレードオフ

あとの段階の設計はその段階になるまで書かない。そのため、前の段階で作ったものをあとの段階で直すことがある。

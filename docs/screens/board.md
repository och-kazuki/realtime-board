# 画面設計：ボード

付箋を貼って操作する画面です。M2 でも、アプリの画面はこの1つだけです。要件は [requirements/m1.md](../requirements/m1.md) と [requirements/m2.md](../requirements/m2.md) にあります。

この設計書には、画面に何があり、どう操作すると何が起きるかを書きます。付箋の位置をボードの端で止める計算や、文字数の数え方など、付箋の状態の決まりは機能設計の [features/notes.md](../features/notes.md) に書きます。サーバーとの同期の仕組みは [features/board-sync.md](../features/board-sync.md) に書きます。

## 画面の構成

```
+----------------------------------------------+
| [1]                              [7]    [2]  |
+----------------------------------------------+
| [3]                                          |
|      +------------+                          |
|      | [4]    [5] |                          |
|      +------------+                          |
|      | [6]        |                          |
|      |            |                          |
|      |            |                          |
|      +------------+                          |
|                                              |
+----------------------------------------------+
```

| 番号 | 部品 | 説明 |
|---|---|---|
| 1 | アプリの名前 | 上の帯に表示する。上の帯はスクロールしても動かない |
| 2 | 「付箋を追加」ボタン | 押すと付箋を1枚追加する |
| 3 | ボード | 上の帯の下の領域に表示する。画面より広く、スクロールして見渡す |
| 4 | 付箋のつまみ | ここをドラッグして付箋を動かす。読み上げ用の名前は「付箋を動かす」 |
| 5 | 削除ボタン（×） | 押すと付箋を消す。読み上げ用の名前は「付箋を削除」 |
| 6 | 付箋の文字 | ダブルクリックすると編集が始まる |
| 7 | 開いている人数 | 上の帯の「付箋を追加」ボタンの左に、「3人が開いています」のように表示する。人数が届くまでと、接続が切れたあとは表示しない |
| 8 | 接続の状態の表示（図にはない） | サーバーとつながっていない間だけ、ボードの領域を覆って表示する（「サーバーとつながっていない間」を参照） |

## ボード

- 大きさは横3000px、縦2000pxです（ADR-014）。画面に入りきらない部分は、スクロールバー、マウスのホイール、タッチパッドでスクロールして見ます。
- スクロールするのは上の帯の下にあるボードの領域だけです。ページ全体はスクロールしません。
- 画面を開いたときは、ボードの左上を表示します。
- ボードの外側は色を変えて、ボードの端がわかるようにします。大きな画面や縮小表示では、ボードが画面より小さく表示されることがあるためです。
- 付箋の位置は、付箋の左上の角がボードの左上からどれだけ離れているかで表します。付箋はボードの外には出せません（ADR-012）。

## 付箋

- 大きさは横200px、縦200pxで、すべての付箋で同じです（ADR-014）。上につまみと削除ボタン、その下に文字を表示します。
- 文字は文字として表示して HTML として解釈させず、改行はそのまま表示します（ADR-010）。付箋の幅に入りきらない行は、空白のない長い英数字も含めて折り返します。
- 付箋に入りきらない文字は付箋の中でスクロールして読みます。
- 付箋が重なったときは、最後に追加・移動・編集を確定した付箋を上に表示します（ADR-012）。ドラッグ中と編集中の付箋はその間だけ一番上に表示します。
- 付箋の要素を並べる順は付箋の `id` の順で固定し、重なりは z-index で表します。重なりの順番が変わるたびに要素を並べ替えると、要素が動いて、入力欄のフォーカスが外れたり、ドラッグが途中で切れたりするためです。

付箋の色や影など、見た目の細かいところは実装で決めます。

## 操作

| 操作 | やり方 | 結果 |
|---|---|---|
| 追加 | 「付箋を追加」ボタンを押す | 空の付箋が1枚増え、その入力欄にカーソルが入る。付箋は、その真ん中が表示中の範囲の真ん中に来るように置く |
| 移動 | 付箋のつまみをマウスの左ボタンでドラッグする | 付箋がマウスについて動き、手を離した位置に残る。ボードの端より外へは動かず、端で止まる |
| 編集を始める | 付箋の文字をダブルクリックする | 付箋の文字が入力欄に変わり、文字の最後にカーソルが入る |
| 編集を確定する | Ctrl+Enter（Mac では ⌘+Enter）を押す。または入力欄の外でマウスのボタンを押す | 入力した文字が付箋に残る |
| 編集を取り消す | Esc を押す | 編集を始める前の文字に戻る |
| 削除 | 削除ボタン（×）を押す | その付箋だけが消える。消す前に確認はしない |

ドラッグ中の付箋の位置と、編集中の文字は、画面だけで持ちます。ドラッグと編集で付箋の状態を変えるのは、手を離したときと、編集を確定したときです。M2 でも、この2つの時点でだけサーバーに操作を送れば済むようにするためです（ADR-015）。つまみを押しただけで動かさなかったときと、文字を変えずに確定したときは、重なりの順番も含めて何も変えません。

### ドラッグ中の付箋

- ドラッグ中の付箋もボードの端より外には表示しません。端で止める計算には、付箋の状態を扱う部分と同じ関数を使います。
- ドラッグ中にスクロールしても、付箋はマウスについて動きます。
- ドラッグ中に Esc を押したときと、ブラウザがポインターの操作を取り消したときは、付箋を元の位置に戻し、付箋の状態は変えません。

### 編集中の付箋

- 編集中の付箋はボード全体で1枚だけです。
- 編集中に入力欄と文字数の表示の外でマウスのボタンを押すと、まず今の編集を確定し、そのあとで押したものの操作をします。上の帯、ボード、スクロールバー、ほかの付箋、同じ付箋のつまみ、「付箋を追加」ボタンを押したときも同じです。
- ただし、編集中の付箋の削除ボタンを押したときは、編集を確定せずに付箋を消します。
- ウィンドウやタブを切り替えただけでは確定も取り消しもしません。
- Enter は確定には使わず、改行の入力に使います。
- 日本語の変換中に押した Ctrl+Enter と Esc は、変換の操作として扱い、確定や取り消しには使いません。
- 入力欄の下に今の文字数と上限を「120 / 200」のように表示します。
- 200字に達しているときに入力した文字は入らず、ほかの文字も変わりません（ADR-011）。
- 貼り付けで上限を超えるときは、貼り付けた文字のうち200字に収まる分だけが入り、ほかの文字は変わりません。カーソルは入った文字の直後に置きます。
- 日本語の変換中は文字数を制限しません。変換を確定して上限を超えるときは、貼り付けと同じく、確定した文字のうち200字に収まる分だけが入ります。
- 文字が空のまま確定しても、付箋は残ります。消すときは削除ボタンを使います。

### 操作中の付箋がなくなったとき

編集中またはドラッグ中の付箋が一覧からなくなったときは、編集やドラッグを終えます。M1 では編集中の付箋を削除ボタンで消したときに起き、M2 ではほかの人が付箋を消したときにも起きます。

## ほかの人の操作

- ほかの人が付箋を追加・移動・削除したり、文字の編集を確定したりすると、自分の画面の付箋もすぐに変わる。動くときのアニメーションは付けない
- ほかの人の操作でも、重なりの順番は変わる。最後に追加・移動・編集を確定した付箋が上に表示される
- 自分が編集中の付箋の文字をほかの人が変えても、入力欄の文字は変えない。確定すると、自分の文字で上書きする（M2 の要件の「同時に操作したとき」）
- 自分がドラッグ中の付箋をほかの人が動かしても、ドラッグは続く。手を離すと、自分が離した位置になる
- 自分の操作はサーバーの結果を待たずに画面に出る。サーバーが受け付けなかったときは、操作する前の表示に戻る。受け付けなかったことは知らせない

## サーバーとつながっていない間

画面を開いてから付箋の一覧が届くまでと、接続が切れたあとは、次のようにします。

- ボードの領域を半透明の覆いで覆い、真ん中に文を表示する。開いた直後は「サーバーに接続しています」、切れたあとは「サーバーとの接続が切れました。ページを再読み込みすると、つなぎ直します」と表示する
- 覆いの下の付箋は操作できない。「付箋を追加」ボタンは押せないようにする
- 編集中の付箋があれば、編集を終える。入力していた文字は確定せずに捨てる
- ドラッグ中に接続が切れたときは、手を離すと付箋が元の位置に戻る

## 設計で決めたこと

| 決めたこと | 理由 |
|---|---|
| ボードの大きさは横3000px、縦2000pxにする | よく使われるパソコンの画面（1920×1080）と比べて横も縦も1.5〜2倍あり、スクロールしないと見渡せない。一方で、付箋が見つからなくなるほど広くはない |
| スクロールするのは上の帯の下のボードの領域だけにする | 上の帯を動かさずに済み、表示中の範囲をこの領域のスクロールの位置と大きさから求められるため |
| 付箋の大きさは固定にし、入りきらない文字は付箋の中でスクロールする | 文字の量で付箋の大きさが変わると、ボードの端で止める計算に、画面に表示したあとの大きさが要る。そうなると、付箋の状態を扱う部分を画面なしでテストできない（ADR-009） |
| 付箋の要素の並びは `id` の順で固定し、重なりは z-index で表す | 要素を並べ替えると、入力欄のフォーカスが外れたり、ドラッグが途中で切れたりするため。M2 でほかの人の操作によって重なりの順番が変わっても、編集中の付箋に影響しない |
| 付箋はつまみをドラッグして動かす | 文字の部分でのドラッグは、文字の選択と付箋の中のスクロールに使う。付箋のどこでもつかめるようにすると、どちらの操作かを見分ける処理が要る |
| ドラッグは Pointer Events で作り、HTML のドラッグ＆ドロップの仕組みは使わない | Firefox では、ドラッグ＆ドロップの `drag` イベントでマウスの座標が 0 になるため |
| 編集の確定は Ctrl+Enter か入力欄の外を押したとき、取り消しは Esc | Enter は改行の入力に使うため（ADR-010）。入力欄の外を押したときに確定すれば、確定し忘れて書いた文字が消えることがない |
| ウィンドウやタブを切り替えただけでは確定しない | ほかのウィンドウを見ただけで編集が終わらないようにするため |
| 編集中の付箋の削除ボタンでは、確定せずに消す | 消す付箋の文字を確定しても意味がないため。M3 で、確定のすぐあとに送る削除が古い `version` のために衝突しないようにする |
| 重なりの順番は、追加・移動・編集を確定したときに変える | 取り消した編集で順番が変わらないようにするため。M2 で、確定した操作だけから全員の画面の重なりの順番をそろえられる |
| 新しい付箋は、表示中の範囲の真ん中に置く | 要件の「表示中の範囲に現れる」を満たす、いちばん単純な置き方のため。続けて追加すると同じ位置に重なるが、最後に追加した付箋が上に表示される |
| サーバーとつながっていない間は、ボードの領域を覆いで覆う | 付箋の部品を1つずつ操作できなくしなくても、まとめて操作できなくできる。何が起きているかも、覆いの文で伝えられる |
| 接続が切れたら、入力していた文字を捨てて編集を終える | 送れない文字を入力欄に残すと、確定できるように見えてしまう。M2 で接続が切れるのは、ほとんどの場合サーバーが止まったときで、そのときは付箋も消えている |
| ドラッグ中に接続が切れても、ドラッグはその場では終えず、手を離したときに元の位置に戻す | ドラッグの処理を接続の状態で止める仕組みを足さずに済む。手を離したときの移動は、ボードのフックが送らない |
| サーバーが受け付けなかった自分の操作は、表示を戻すだけで知らせない | M2 で受け付けられないのは、ほとんどがほかの人の消した付箋への操作で、その付箋は画面からも消えているため |

## M1 で作らないこと

要件の対象外（[requirements/m1.md](../requirements/m1.md) の「対象外」）に加えて、この画面では次のものも作りません。

- ドラッグ中に付箋が画面の端に来たとき、自動でスクロールすること。遠くへ動かすときは、いったん手を離してスクロールしてから、もう一度ドラッグします
- ボードの空いている所をドラッグして、表示する範囲を動かすこと
- ボードの拡大と縮小
- キーボードだけで付箋を動かすこと

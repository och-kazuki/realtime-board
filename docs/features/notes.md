# 機能設計：付箋の状態

付箋の一覧を持ち、追加・移動・文字の変更・削除の操作を受けて一覧を更新する部分の設計です。画面でどう操作するかは [screens/board.md](../screens/board.md) にあります。

この部分は次の2つに分けます。

| 部分 | 役割 |
|---|---|
| 状態の関数 | 今の状態と操作を受け取り、次の状態を返す。React の `useReducer` に渡す |
| ボードのフック | 付箋の一覧と、追加・移動・文字の変更・削除の4つの関数を画面の部品に渡す。画面の部品は、付箋についてはこのフックだけを使う |

状態の関数には画面の部品と通信の処理を入れません（ADR-009）。入力だけで結果が決まるので、画面を動かさずにテストできます。M2 で通信の処理が入るのはボードのフックだけです。

## 付箋のデータ

| 項目 | 型 | 内容 |
|---|---|---|
| `id` | 文字列 | 付箋を見分けるための UUID。ボードの中で付箋ごとに違う |
| `text` | 文字列 | 付箋の文字。200字まで。空でもよい |
| `x` | 整数 | 付箋の左上の角の、ボードの左端からの距離（px） |
| `y` | 整数 | 付箋の左上の角の、ボードの上端からの距離（px） |

状態は付箋の一覧です。一覧の並び順を重なりの順番として使い、後ろにある付箋ほど上に表示します。

## 状態の関数が受け取る操作

| 操作 | 渡すもの | 結果 |
|---|---|---|
| 追加 | `id`、`x`、`y` | 文字が空の付箋を一覧の最後に加える。位置はボードの範囲に収める |
| 移動 | `id`、`x`、`y` | 付箋の位置を変え、一覧の最後に移す。位置はボードの範囲に収める |
| 文字の変更 | `id`、`text` | 付箋の文字を変え、一覧の最後に移す |
| 削除 | `id` | 付箋を一覧から除く。ほかの付箋の順番は変えない |

次の操作では何も変えず、元の状態をそのまま返します。

- 一覧にない `id` を指定した移動、文字の変更、削除
- 一覧にすでにある `id` を指定した追加
- 位置に数でない値（`NaN` や `Infinity`）を指定した追加と移動
- 200字を超える文字への変更

今と同じ位置への移動と、今と同じ文字への変更は、ほかの操作と同じように反映し、付箋を一覧の最後に移します。M2 ではサーバーから届いた操作をそのまま反映して、どの画面でも重なりの順番をサーバーと同じにするためです。同じ値の操作を作らないようにするのは、ボードのフックの役割です。

## ボードのフック

4つの関数は画面から受け取ったものを、状態の関数が受け取る操作に変えて渡します。

| 関数 | 画面から受け取るもの | すること |
|---|---|---|
| 追加 | 置く位置 | UUID で `id` を作り、追加の操作を渡す。作った `id` を返す |
| 移動 | `id`、位置 | ボードの範囲に収めたあとの位置が今と同じなら何もしない。違えば移動の操作を渡す |
| 文字の変更 | `id`、文字 | 今と同じ文字なら何もしない。違えば文字の変更の操作を渡す |
| 削除 | `id` | 削除の操作を渡す |

移動と文字の変更の関数は、一覧にない `id` や数でない位置を受け取ったときも、操作を渡さずに何もしません。今の値と比べられないためです。渡しても、状態の関数は何も変えません。

追加の関数が `id` を返すのは、追加した付箋の編集を画面がすぐに始められるようにするためです。`id` は M2 以降もブラウザが決め、サーバーには決めた `id` を送ります（ADR-016）。こうすると、追加した付箋をすぐ編集する流れを M2 でも変えずに済みます。

UUID の作り方は限定しません。`crypto.randomUUID()` は HTTPS か localhost で開いたときにしか使えないので、M2 でほかのパソコンから HTTP で開くときは別の作り方が要ります。

## 位置の決まり

付箋はボードの外に出せません（ADR-012、ADR-014）。追加と移動で渡された位置は、次の順に直してから使います。

1. 小数は四捨五入して整数にする
2. `x` が 0 より小さければ 0 に、2800 より大きければ 2800 にする
3. `y` が 0 より小さければ 0 に、1800 より大きければ 1800 にする

2800 はボードの横幅 3000px から付箋の横幅 200px を引いた値で、1800 はボードの縦幅 2000px から付箋の縦幅 200px を引いた値です。ボードと付箋の大きさは1か所で決め、画面と状態の両方がその値を使います。

この計算は1つの関数にまとめ、状態の関数、ボードのフック、ドラッグ中の表示のどれもがその関数を使います。

## 文字数の数え方

ADR-011 で決めた200字は、Unicode のコードポイントの数で数えます（ADR-013）。改行も1字と数えます。

JavaScript の `text.length` は UTF-16 の単位で数えるので、一部の絵文字を2字と数えます。コードポイントの数は `Array.from(text).length` で数えられ、M2 の Go のサーバーでは `utf8.RuneCountInString` で同じ数を数えられます。入力欄の `maxLength` も UTF-16 の単位で数えるため、文字数の制限には使いません。

肌の色を変えた絵文字のように、見た目は1文字でも2字以上と数える文字があります。付箋に書く短いメモでは困らないと考えています。

## 状態に入れないもの

次のものは画面だけで持ち、この状態には入れません。

- ドラッグ中の付箋の位置
- 編集中の付箋がどれかと、編集中の文字
- ドラッグ中と編集中の付箋を一時的に一番上に表示すること
- スクロールの位置

この状態には M2 でほかの人と共有するものだけを入れます。上のものは操作している本人の画面にだけ関わるので、M2 でもサーバーに送りません（ADR-015）。

## M2 への備え

M2 ではボードのフックの中身だけを替えます。4つの関数は操作をサーバーに送り、サーバーから届いた通知を状態の関数への操作に変えて渡します。画面の部品は変えません。

状態の関数には、スナップショットで一覧を置き換える操作のように、M2 以降で操作を足します。今ある操作の意味は変えません（ADR-009）。

操作のデータの形は M2 で画面とサーバーの取り決め（`interfaces/`）を書くときに見直します。M1 には画面とサーバーの取り決めがないので、`interfaces/` は書きません。

## 受け入れ条件の確かめ方

自動テストは、状態の関数、ボードのフック、画面の部品のそれぞれについて書きます。画面の部品のテストで使う jsdom には画面の配置の計算がないので、スクロールの位置や見た目は手動で確かめます。手動の確認は、Chrome、Edge、Firefox の最新版で行います。

| ID | 確かめる場所 |
|---|---|
| M1-AC-01 | 状態のテスト（追加すると空の付箋が1枚増え、渡した位置に置かれる）、表示中の範囲の真ん中を求める関数のテスト、画面の部品のテスト（追加した付箋の入力欄にカーソルが入る） |
| M1-AC-02 | 状態のテストと、画面の部品のテスト（つまみをドラッグして離すと、その位置に残る） |
| M1-AC-03 | 状態のテストと、画面の部品のテスト（ドラッグ中の付箋もボードの端で止まる） |
| M1-AC-04 | 手動 |
| M1-AC-05 | 状態のテスト（文字を変更すると内容が変わる）と、画面の部品のテスト（取り消すと編集前の文字に戻る） |
| M1-AC-06 | 状態のテスト（200字を超える変更では何も変わらない）、画面の部品のテスト（末尾と途中への入力と貼り付けで200字を超えない）、手動（日本語の変換を確定したとき） |
| M1-AC-07 | 状態のテストと、画面の部品のテスト（削除ボタンを押すと、その付箋だけが消える） |
| M1-AC-08 | 状態のテスト（追加・移動・文字の変更をした付箋が一覧の最後に来る）と、画面の部品のテスト（一覧の最後の付箋の z-index が一番大きい） |
| M1-AC-09 | 画面の部品のテスト |
| M1-AC-10 | 画面の部品のテスト（改行を含む文字がそのまま入り、改行を表示するスタイルが付く）と、手動（改行して見える） |
| M1-AC-11 | 設計とコードのレビュー（画面の部品が付箋についてボードのフックだけを使い、状態の関数を直接使っていない） |

## 設計で決めたこと

| 決めたこと | 理由 |
|---|---|
| 画面の部品は、付箋についてはボードのフックだけを使う | M2 でフックの中身を替えるだけで通信をつなげ、画面の部品を変えずに済むため（要件の「通信の部分だけを差し替えられる作り」） |
| 重なりの順番は一覧の並び順で表す | 順番のための項目が要らず、付箋を一番上に出すには一覧の最後に移すだけで済む |
| 同じ値かどうかはボードのフックで判定し、状態の関数は届いた操作をそのまま反映する | M2 で、どの画面でも重なりの順番をサーバーと同じに保つため |
| 位置は整数にする | 見た目では同じ位置なのに、小数の差で別の位置と扱われないようにするため |
| 文字数は Unicode のコードポイントの数で数える | M2 で、Go のサーバーも標準ライブラリだけで同じ数を数えられるため。見た目の1文字ごとに数えるには、Go では標準ライブラリにない仕組みが要る |
| 200字を超える文字への変更は、切り詰めずに何も変えない | 画面で上限を超えないようにしているので、上限を超える変更がここに届くのは誤りのときだけになる。M2 で、上限を超える操作をサーバーが受け付けないのと同じ扱いにする |
| 付箋の `id` は、M2 以降もブラウザが UUID で決める | 追加した付箋をすぐ編集する流れを、M2 でも変えずに済むため。状態の関数の中で作らないので、状態の関数は入力だけで結果が決まる |

# 取り決め：画面とサーバーのメッセージ

画面とサーバーが WebSocket でやり取りするメッセージの形と、画面とサーバーの両方で同じに当てる決まりです。画面の側の処理は [features/board-sync.md](../features/board-sync.md)、サーバーの側の処理は [features/board-server.md](../features/board-server.md) にあります。

## つなぎ方

- 画面はページを開いたときに、ページと同じホストの `/ws` へ WebSocket でつなぐ（`ws://<ページのホスト>/ws`）
- 開発では、Vite の開発サーバー（`localhost:5173`）が `/ws` を Go のサーバー（`127.0.0.1:8080`）へ中継する
- メッセージはすべてテキストのメッセージで、中身は JSON のオブジェクト1つとする。種類は `type` で分ける
- 画面からサーバーへ送る1つのメッセージは、4096 バイトまでとする

4096 バイトは200字の文字を送る `note.updateText` にも十分な大きさです。文字を JSON に書くと1字が最大で6バイト（`\u0000` の形）になり、200字では1200バイトになります。

## 付箋の形

| 項目 | 型 | 決まり |
|---|---|---|
| `id` | 文字列 | UUID の形（16進数の8-4-4-4-12桁）。大文字と小文字はどちらでもよい。ボードの中で付箋ごとに違う（ADR-016） |
| `text` | 文字列 | 200字まで。Unicode のコードポイントで数える（ADR-011、ADR-013） |
| `x` | 整数 | 0 以上 2800 以下（ADR-014） |
| `y` | 整数 | 0 以上 1800 以下（ADR-014） |

## 画面からサーバーへ

| `type` | 中身 | 意味 |
|---|---|---|
| `note.create` | `requestId`、`id`、`x`、`y` | 文字が空の付箋を追加する |
| `note.move` | `requestId`、`id`、`x`、`y` | 付箋を動かす |
| `note.updateText` | `requestId`、`id`、`text` | 付箋の文字を変える |
| `note.delete` | `requestId`、`id` | 付箋を消す |

`requestId` は、画面が自分の送った操作の結果を見分けるための文字列です。画面が操作ごとに UUID で決めます。サーバーは中身を確かめずに、結果のメッセージにそのまま付けて返します。

```json
{ "type": "note.move", "requestId": "5b0c…", "id": "9f2e…", "x": 120, "y": 340 }
```

## サーバーから画面へ

| `type` | 中身 | 送る相手 | 送るとき |
|---|---|---|---|
| `snapshot` | `notes`（付箋の一覧。重なりの順番に並べる） | 接続した本人 | 接続した直後に1回 |
| `note.created` | `requestId`、`id`、`x`、`y` | ボードを開いている全員 | `note.create` を受け付けたとき |
| `note.moved` | `requestId`、`id`、`x`、`y` | ボードを開いている全員 | `note.move` を受け付けたとき |
| `note.textUpdated` | `requestId`、`id`、`text` | ボードを開いている全員 | `note.updateText` を受け付けたとき |
| `note.deleted` | `requestId`、`id` | ボードを開いている全員 | `note.delete` を受け付けたとき |
| `presence` | `count`（開いている画面の数） | ボードを開いている全員 | 画面が接続したときと、接続が切れたとき |
| `error` | `requestId`、`code`、`message` | 操作を送った本人 | 操作を受け付けなかったとき |

`note.created` などの4つは受け付けた操作の中身をそのまま配ります。操作した本人にも配るので、本人は `requestId` で自分の操作が受け付けられたことを知ります。

`error` の `code` は次の3つです。`message` は調べるときのための説明で、画面には表示しません。

| `code` | 受け付けなかった理由 |
|---|---|
| `invalid` | 値が決まりに合わない（UUID の形でない `id`、200字を超える文字、整数でない位置、ボードの範囲の外の位置） |
| `already_exists` | 追加しようとした `id` の付箋がすでにある |
| `not_found` | 移動、文字の変更、削除をしようとした付箋がない |

## サーバーが接続を切るとき

次のときは、サーバーは `error` を返さずに接続を切ります。正しく作った画面からは届かないメッセージだからです。

| とき | 接続を閉じるときのコード |
|---|---|
| JSON として読めない。`type` が上の4つのどれでもない。項目が足りないか、型が違う（数のはずの位置が文字列など） | 1008（決まりに反する） |
| メッセージが 4096 バイトを超える | 1009（大きすぎる） |
| 画面がメッセージを受け取らず、送るメッセージがたまりすぎた。または、サーバーを止める | 1013（あとでやり直す） |

画面はどのコードで切られても同じに扱い、つなぎ直しません（M2 の要件）。

## 画面とサーバーで同じに当てる決まり

付箋の一覧の並び順を重なりの順番とし、後ろにある付箋ほど上に表示します（ADR-012）。画面の付箋の状態の関数と、サーバーのボードの状態は、次の決まりで一覧を変えます。あとから開いた人の画面はサーバーの一覧の順番をスナップショットで受け取り、前から開いている人の画面は届いた操作から順番を作ります。そのため、2つの決まりが少しでも違うと、あとから開いた人の画面だけ重なりの順番がずれます。

| 操作 | 一覧の変え方 |
|---|---|
| 追加 | 一覧の最後に加える |
| 移動 | 位置を変え、一覧の最後に移す。今と同じ位置でも移す |
| 文字の変更 | 文字を変え、一覧の最後に移す。今と同じ文字でも移す |
| 削除 | 一覧から除く。ほかの付箋の順番は変えない |

サーバーは受け付けた操作だけを、受け付けた順に全員へ配ります。画面は届いた順に操作を反映します。

この決まりの例を `docs/interfaces/note-operations.json` に置きます。例は操作の並びと、反映したあとの一覧の組です。Go のテストと TypeScript のテストが同じ例を読み、両方の結果が例と同じになることを確かめます。例には、サーバーが受け付ける操作だけを入れます。決まりに合わない操作の扱いは画面とサーバーで違う（画面の付箋の状態の関数は範囲の外の位置を収め、サーバーは受け付けない）ので、それぞれのテストで別に確かめます。

## M3 で足す予定のもの

付箋ごとの `version`（ほかの人の変更を気づかないうちに上書きしないため）と、ボードごとの通し番号 `seq`（つなぎ直したときに、手元の状態とスナップショットのどちらが新しいかを確かめるため）は、M3 で足します。M2 の画面とサーバーは、知らない項目があっても無視します。

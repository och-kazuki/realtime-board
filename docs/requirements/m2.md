# M2 要件：みんなで見えるボード

## 目的

Go の WebSocket サーバーを作り、ほかの人の操作がすぐに自分の画面にも反映されるボードにします。ねらいは次の2つです。

- ロードマップの Phase 4 で学んだ Go を、別の題材で使う。特に、goroutine と channel による並行処理と、WebSocket によるリアルタイムの通信を学ぶ
- M1 で作った画面を、付箋の状態の関数の今ある操作を変えずにサーバーとつなぐ（ADR-009）

ボードは1つだけで、付箋はサーバーのメモリに持ちます。同じパソコンの複数のブラウザやタブでボードを開いて、共有を確かめます。

## できること

1. ボードの画面を開くと、サーバーにある付箋が、位置、文字、重なりの順番もそのままで表示される
2. 付箋を追加・移動・文字の編集・削除すると、同じボードを開いているほかの画面にもすぐに反映される。移動は手を離したとき、文字の編集は確定したときに反映する（ADR-015）
3. M1 でできた操作は M2 でも同じようにできる。追加した付箋にすぐ文字を入力できることも含む
4. 付箋が重なったときの順番は、すべての画面で同じになる（ADR-012）
5. いまボードを開いている画面の数が表示される。画面を開いたり閉じたりすると、すべての画面で表示が変わる
6. 自分が編集中またはドラッグ中の付箋をほかの人が削除すると、自分の画面でもその付箋が消え、編集やドラッグが終わる
7. サーバーとつながっていない間は、そのことが画面に表示され、付箋を操作できない。接続が切れたときは、ページを再読み込みするとつなぎ直せる

## 同時に操作したとき

- サーバーは届いた操作を届いた順に1つずつ処理し、その順番のまますべての画面に配る
- 同じ付箋を2人が操作したときは、あとからサーバーに届いた操作の結果が残る。たとえば2人が同じ付箋の文字を編集して確定すると、先に届いた文字は上書きされ、先に確定した人にもそのことは知らされない。上書きを防ぐ仕組みは M3 で入れる
- ほかの人が削除した付箋への操作（消された付箋で手を離したり、編集を確定したりしたとき）は、サーバーが受け付けず、どの画面にも反映されない

## 機能以外の要件

- サーバーは Go で作り（ADR-004）、ブラウザとは WebSocket で通信する（ADR-005）。サーバーのコードは `server/` に置く（ADR-007）
- 付箋はサーバーのメモリにだけ持つ。サーバーを止めると付箋は消える
- サーバーはブラウザから届いた操作を必ず確かめ、次の決まりに合わない操作は直さずに受け付けない（ADR-017）。ブラウザ側の確認は使いやすさのためのもので、サーバーの確認の代わりにはしない
  - 付箋の `id` は UUID の形で、ほかの付箋の `id` と同じでない（ADR-016）
  - 付箋の文字は200字まで。Unicode のコードポイントで数える（ADR-011、ADR-013）
  - 付箋の位置は整数で、ボードの範囲の中にある（ADR-012、ADR-014）
- サーバーは自分の画面以外のサイトからの WebSocket の接続を受け付けない
- サーバーは大きすぎるメッセージを受け付けない
- 1つの画面の通信が遅れたり止まったりしても、ほかの画面への反映は遅らせない
- 接続が切れたら、その接続のために動かしていた goroutine をすべて終わらせる
- 付箋の操作をサーバーに送る処理は、ボードのフックの中にだけ入れる。画面の部品と付箋の状態の関数には通信の処理を入れない（ADR-009）。状態の関数の今ある操作の意味は変えない
- 付箋の状態の関数と画面の部品の自動テストは、サーバーを動かさずに実行できるようにする
- サーバーと画面を手元で起動する手順と、それぞれのテストを実行する手順を用意する
- 対応する環境は M1 と同じく、パソコンの最新の Chrome、Edge、Firefox とする。ボードは localhost で開き、ほかのパソコンからは開かない

## 対象外

| 対象外のこと | 入れる段階 |
|---|---|
| 再読み込みやサーバーの再起動のあとも付箋が残ること | M3（DB に保存する） |
| 複数のボード、ボードの作成、URL での共有 | M3 |
| ほかの人の変更を、気づかないうちに上書きしないこと | M3 |
| 接続が切れたときに、自動でつなぎ直すこと | M3 |
| ログイン、ボードのメンバーと権限 | M4 |
| ほかのパソコンから開くこと、インターネットへの公開 | M4 |
| 1つの接続から送れる操作の回数の上限 | M4 |
| ドラッグ中の位置と編集中の文字の共有 | 作らない（ADR-015） |
| ほかの人のカーソルの表示、元に戻す、付箋の色と大きさの変更 | 未定 |
| スマートフォンとタブレットでの操作 | 未定 |

## 受け入れ条件

この表の「画面」はボードを開いているブラウザのタブ1つを指します。

| ID | 条件 | 確かめ方 |
|---|---|---|
| M2-AC-01 | ボードを開くと、それまでにほかの画面で追加・変更された付箋が、位置、文字、重なりの順番もそのままで表示される | 自動テスト |
| M2-AC-02 | 付箋を追加すると、ほかの画面にも同じ位置に空の付箋が現れる | 自動テスト |
| M2-AC-03 | 付箋を動かして手を離すと、ほかの画面でもその付箋が同じ位置に移り、一番上に表示される | 自動テスト |
| M2-AC-04 | 文字の編集を確定すると、ほかの画面でもその付箋の文字が変わる。編集中と、編集を取り消したときは、ほかの画面は変わらない | 自動テスト |
| M2-AC-05 | 付箋を削除すると、ほかの画面からもその付箋だけが消える | 自動テスト |
| M2-AC-06 | 複数の画面から同時に操作しても、最後にはすべての画面で付箋の位置、文字、重なりの順番が同じになる。同じ付箋への操作はあとからサーバーに届いたものの結果が残る | 自動テスト |
| M2-AC-07 | 自分が編集中またはドラッグ中の付箋をほかの画面で削除すると、自分の画面でもその付箋が消え、編集やドラッグが終わる | 自動テスト |
| M2-AC-08 | ボードを開いている画面の数が表示され、画面を開いたり閉じたりすると、すべての画面で数が変わる | 自動テスト |
| M2-AC-09 | サーバーとつながっていない間は、そのことが表示され、付箋の追加・移動・編集・削除ができない | 自動テスト |
| M2-AC-10 | 決まりに合わない操作は、サーバーが受け付けず、どの画面にも反映されない。決まりに合わない操作には、UUID の形でない `id`、すでにある `id` での追加、200字を超える文字、整数でない位置とボードの範囲の外の位置、ない付箋への操作、形の壊れたメッセージを含む | 自動テスト |
| M2-AC-11 | 自分の画面以外のサイトからの接続と、大きすぎるメッセージを送った接続は、サーバーが受け付けない | 自動テスト |
| M2-AC-12 | 1つの画面がメッセージを受け取らなくなっても、ほかの画面には操作が反映され続ける | 自動テスト |
| M2-AC-13 | 接続が切れると、その接続のために動いていた goroutine がすべて終わる | 自動テスト |
| M2-AC-14 | サーバーの自動テストを、データ競合を見つける設定（`go test -race`）で実行しても、競合が見つからない | 自動テスト |
| M2-AC-15 | M1 の受け入れ条件 M1-AC-01〜10 を M2 でも満たす。M1 で書いた自動テストは、確かめる内容を変えずに、サーバーを動かさずに通る。テストの準備は変えてよい | 自動テストと手動 |
| M2-AC-16 | 実際のブラウザで2つの画面を開くと、片方での追加・移動・編集・削除がもう片方にすぐ反映され、開いている画面の数も正しく表示される | 手動 |
| M2-AC-17 | 付箋の操作をサーバーに送る処理がボードのフックの中にだけあり、画面の部品と付箋の状態の関数に通信の処理が入っていない | 設計とコードのレビュー |

M2-AC-01〜09 はサーバーの自動テスト（Go）と画面の自動テスト（TypeScript）を組み合わせて確かめます。どの条件をどちらで確かめるかは、[features/board-sync.md](../features/board-sync.md) の「受け入れ条件の確かめ方」にあります。

## 決めたこと

| 決めたこと | 理由 |
|---|---|
| ボードは同じパソコンから localhost で開き、ほかのパソコンからは開かない | `crypto.randomUUID()` をそのまま使え、許可する接続元も localhost だけで済む。ほかのパソコンから開くことは、公開する M4 で扱う |
| 開いている人数は接続している画面（タブ）の数で数える。同じ人が2つのタブで開くと2と数える | ログインがない M2 では、人を見分けられないため |
| 同じ付箋への操作は、あとからサーバーに届いたものを残す | 上書きを防ぐ仕組みは同時に編集したときの扱いとして M3 で入れる（overview.md） |
| 接続が切れたら操作できなくし、自動でつなぎ直すことはしない | M2 では付箋をサーバーのメモリにだけ持つ。localhost で接続が切れるのは、ほとんどの場合サーバーが止まったときで、そのときは付箋も消えているので、つなぎ直しても得るものが少ない |
| 自分の画面以外のサイトからの接続の拒否と、メッセージの大きさの上限は M2 で入れる。操作の回数の上限は M4 に回す | 前の2つは WebSocket のライブラリの設定で入れられる。また、ブラウザで開いたほかのサイトのページからも、localhost のサーバーに接続できてしまう。操作の回数の上限は公開するときに必要になる |
| ボードの範囲の外の位置が届いたら、サーバーは範囲に収めずに操作を受け付けない（ADR-017） | 画面は範囲に収めてから送るので、範囲の外の位置が届くのは誤りのときだけになる。200字を超える文字を受け付けないのと同じ扱いにする |
